# G35：游标恢复与轮询降级

后端 Last-Event-ID 优先于 afterSequence，严格检查 Run、规范正整数及已提交最大序号。JSON/SSE 同一补读来源，严格大于游标；错误游标 400，不隐式切换任务。客户端断开异常不再尝试向已关闭的 SSE 写普通 JSON 错误。

前端每个 Run 保存连续序号和最近事件轨迹；刷新先 GET 原 Run、再从游标补读，仅显式点击创建/重新运行会 POST。事件校验 runId/eventId/sequence/类型/状态，重复忽略、跨 Run 和跳号触发补读，游标只在成功交付连续事件后前进。旧连接和旧 HTTP 响应受执行代际及 AbortSignal 隔离。

SSE 不可用时每两秒轮询持久事件，重连按指数退避并设上限；终态补齐后停止连接/计时器并读取 reportId。中止等待和页面退出不会调用取消接口。localStorage 不可用时保留内存游标，损坏存储从头安全重读；历史侧栏始终可重新打开。

验收包括存储刷新、重复、乱序、缺口、断网恢复、轮询、重连、旧连接迟到、HTTP 中止、终态关闭和后端 Last-Event-ID 负面场景；所有测试不调用外部模型。

最终回归：后端 335 项、前端 35 项全部通过，类型检查/生产构建、G01 24 项拒绝及实际已发布报告 Schema 通过。实际重启后端、从历史打开原报告并刷新页面，仍是同一 runId/reportId/snapshotHash，恢复全部 16 条真实事件，未新建研究。截图保存在忽略的 backend/target/g35-workbench.png，仅为合成验收记录。
