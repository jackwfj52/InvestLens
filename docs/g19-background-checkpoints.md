# G19：后台执行与原子检查点

默认开启数据库调度，每 500ms 扫描，固定两个工作线程、两个提交许可及有界队列。任务先取得执行容量，工作线程内才领取数据库任务，避免排队占用租约；拒绝提交不会领取 Run。可用 `investlens.workflow.scheduler.enabled=false` 关闭扫描，测试显式关闭或开启真实调度。

HTTP 202 提交后不等待处理器；浏览器停止等待不停止后台任务。领取、处理、检查点分别执行，处理器不占调度事务。V10 的 step_outputs 保存 inputHash、outputHash、执行版本及 JSON，复合外键保护 Run/Step 归属。输出、Step 成功/失败、事件、下一 PENDING 步骤同事务；插入事件失败会回滚整个检查点。输出成功提交后才存在下一步骤。进程中断保留未完成租约，旧令牌写入仍被拒绝。

当前真实执行链：PLAN 固定输入计划 → RESEARCH 核对原组合和显式市场输入缺口 → QUANT 用原权重计算含现金的 HHI/最大权重 → BULL 明确失败 PROVIDER_NOT_CONFIGURED。Research 不发外部请求、不猜行情窗口；Quant 不虚构收益、冲击或 MetricBundle，HHI 使用十进制及既有 weight-concentration-v1 定义。尚未实现的多空/裁决处理器明确缺失，Run 最终 FAILED、无 reportId。已成功的准备步骤及失败诊断仍可从数据库检查，不冒充完整研究报告。

验收：20 项 G16—G19 相关测试全部通过。新增覆盖输出/事件/下一步骤原子提交、事件故障全回滚、重复及过期写入拒绝、两个工作者容量上限、执行中断无伪成功。真实 HTTP 在阻塞处理器结束前返回 202，释放后自动推进三个成功检查点并以明确缺配置终止；固定 20/10/70 权重 HHI 为 0.54，所有成功步骤均能重读真实输出。

正式历史 Research/Quant、模型处理器、完整重启复用和报告发布仍按后续分组接入。
